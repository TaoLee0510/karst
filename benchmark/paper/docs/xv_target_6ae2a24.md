# Cross-validation "compared against what" aligned to alfak: round 6ae2a24

2026-11-21. Diagnosis only; the KARST package itself was not changed.

## 1. Problem

The cross-validation of the two methods uses the same folds (each frequent karyotype together with its one-step neighbours), and both report alfak's R2R, but what the held-out prediction is "compared against" differs:

| | Held-out prediction | Compared against |
|---|---|---|
| alfak (alfakR dev2 f93b2d2, `xval()`) | Kriging refit on the values of the other karyotypes | one bootstrap draw of that karyotype's first-step fitness; it comes mainly from its own counts and carries sampling noise |
| KARST (`as_alfak()`, `sparse_joint_alfak_xval()`) | the counts of this fold removed, the posterior mode recomputed | KARST's estimate from all the data; it comes from the same smoothing model as the held-out prediction |

As a result KARST's scores are generally very high: the median for Salehi two time points is 0.75, for alfak −0.15. The paper's tests first keep only fits with score > 0, then choose minobs and window length by score, so this difference changes which fits of each method enter the evaluation.

The question this report answers: where KARST falls behind in the paper's tests, for example in the ranking of Fig. 2d, how much of it comes from this difference.

## 2. Method

**Step 0: karyotype sets.**
- `scripts/check_ksets.R` now covers the three KARST methods and stops with an error as soon as any pair of sets differs. `hpc/collect_analyse.sh` runs it before all analyses.
- Each analysis script also reads `tables/ksets.Rds` at the start (`require_same_ksets()`, `R/xv_source.R`).
- Result of this round: ABM 10 622 pairs, missegregation-rate simulations 1125 pairs, Salehi 2366 pairs (`karst`, `karst_pairwise`, `karst_state_space` together); all three sets, karyotypes, frequent karyotypes and one-step neighbours, are identical.

**Step 1: the same target value** (`scripts/xv_alfak_target.R`, output `tables/xv_alfak_target.Rds`).
- The `xval.Rds` of both sides store, for each tested karyotype, the target value (`observation`) and the held-out prediction (`prediction`).
- The new KARST score = R2R(alfak's target values, KARST's held-out predictions), computed only on karyotypes tested by both sides.
- alfak is also recomputed once on the same karyotypes ("alfak same set"), and the Pearson correlation is given for both sides. R2R penalises a mismatch of scale, and alfak's fitness differences are too large, so Pearson serves as a reference that is not affected by scale.
- When the alfak fit failed, there is no target value, or fewer than 2 karyotypes are tested by both sides, KARST has no score (D1: option a). The paper's rule excludes such fits.
- Check: recomputing the stored scores of both methods from the stored pairs with alfak's R2R formula gives a maximum difference of 2.3e-13.

**Step 2: rerun the tests that select by score.**
- With `XV_SOURCE=alfak_target` set, KARST fits read the new score instead; alfak and the paper's own fits keep their original scores. Results are written to `analysis_xv_alfak_target/` and `figures_xv_alfak_target/`; the default results are untouched.
- Tests rerun:
  - ABM and missegregation-rate simulations: `analyse_abm.R`;
  - Salehi: `analyse_salehi.R`, including Fig. 2b–f and Fig. 3;
  - Fig. 4–6: for Fig. 4 and Fig. 6 only the four KARST groups are rerun, and the three alfak and paper groups are copied from `analysis/fig456/`; Fig. 5 is rerun in full;
  - `summary_comparison.R`.
- The comparison tables are generated by `scripts/xv_target_report.R`, in `analysis_xv_alfak_target/xv_target/`. This script checks that the rows of the alfak and paper fits are identical in the two runs, and raises an error otherwise. This time all are identical.

- **Extent of the shared karyotypes:**

- **The Spearman between new and old scores is 0.39–0.71.** The new score is not a simple shift of the old one.

## 7. Conclusions

1. **Most of the Fig. 2d deficit comes from what cross-validation "compares against".** About two-thirds with two time points; on the rows selected by KARST's new score, the two methods rank the same (−0.004). About 44% with all time points; the gap of anchored on all rows (−0.26, interval contains 0) has nothing to do with selection.
2. **With the same target, KARST's score falls on the same scale as alfak's.** It reflects true accuracy no worse than alfak's does. But on Salehi both scores can hardly predict forecast quality, so selection by score is itself of limited value.
3. **Other tests:** Fig. 2f improves, Fig. 3 is unchanged, Fig. 2c gets worse but is still no worse than alfak, Fig. 4–6 has gains and losses, ABM is almost unchanged. The tests where KARST led before it still leads.
4. **Next step (D3: option a):** whether to add to the KARST package a like-for-like target that does not depend on alfak (fitness estimated from that karyotype's own counts only, plus one draw of its own noise) is for you to decide after reading this report.

## 8. Limitations

- **The new score depends on alfak.** It uses the target values of the alfak fit: when alfak fails KARST has no score, and a user who runs KARST on its own cannot obtain it either.
- **alfak's target itself carries alfak's bias.** Its fitness differences are too large. So R2R is on the strict side for KARST, and Pearson is fairer.
- **On ABM, KARST only tests karyotypes inside the model domain:** the shared karyotypes are only 50–83% of alfak's.
- **Scripts not switched:** `cv_score_analysis.R` (reads `xval.Rds` directly), `example_abm.R`, the multi-horizon test and the Fig. 2d denoising. The last two do not select by score and are not affected.
